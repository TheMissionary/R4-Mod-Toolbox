## 3. Critical Architectural Learnings & Protocols

1. **Svelte 5 HTML Parser vs. TypeScript Non-Null Assertions:**
   * While TypeScript non-null assertions (`!`) are valid inside `<script>` blocks, Svelte 5's template compiler rejects them inside markup or `{@const}` blocks, throwing a fatal Rolldown `Unexpected token` error. Always use standard optional chaining (`?.`) in Svelte HTML templates.
2. **Intersection Observers for CSS-Hidden Tab Animations:**
   * When switching tabs via CSS display classes (`class="hidden"`) rather than mounting/unmounting, Svelte's `onMount` fires immediately on application startup for all tabs. To trigger animations (such as the Ko-fi glow) reliably on tab activation, an `IntersectionObserver` action must be attached to the target DOM node.
3. **PowerShell Single-Quoted Here-Strings (`@' ... '@`):**
   * Double-quoted here-strings (`@" ... "@`) in PowerShell attempt variable interpolation on Svelte runes (`$state`, `$derived`, `$props`), corrupting source files with escaped characters or empty strings. All automated file deployments containing Svelte files MUST use single-quoted here-strings (`@' ... '@`).
4. **Markdown Buffer Ceilings & Large Component Deployments:**
   * Files exceeding ~500 lines risk overflowing the LLM markdown response buffer, truncating scripts mid-stream. When large components (like `ArchiveView` or `+page.svelte`) must be deployed, split-merge operations must be encapsulated within a single, unified PowerShell execution block to prevent local file desyncs.
5. **Lucide-Svelte Export Strictness:**
   * Avoid unverified brand icon exports (e.g., `Github`, `Kofi`). Always stick to verified standard icons (`Code`, `Coffee`, `ExternalLink`, `Settings`).
